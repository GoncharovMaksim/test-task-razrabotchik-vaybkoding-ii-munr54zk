     КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО привязывать проект Vercel к репозиторию HanterProV2 или любым другим существующим репозиториям аккаунта!
   - КРИТИЧЕСКИЕ ПРАВИЛА ДЛЯ VERCEL SERVERLESS:
     * ХРАНИЛИЩЕ ДАННЫХ: Файловая система на Vercel READ-ONLY! КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО писать в локальные файлы типа 'data/games.json' или надеяться на постоянный диск. Ошибки fs.writeFileSync приведут к потере данных и сбросу при каждом cold start! Для постоянных данных используй облачную БД (Supabase / Neon PostgreSQL / Turso / Vercel KV / Upstash Redis), либо изолированный mock-free in-memory с явной маркировкой, либо гарантируй полноценный запуск с постоянным томом через Docker Compose.
     * РАСПИСАНИЕ И ШЕДУЛЕР (CRON): 'setInterval' в Vercel лямбдах НЕ РАБОТАЕТ, так как процесс засыпает после ответа. Если в ТЗ требуется запуск по расписанию (например, 1 раз в час), ОБЯЗАТЕЛЬНО добавь в корень проекта файл 'vercel.json' с конфигурацией crons:
       {
         "crons": [
           { "path": "/api/cron", "schedule": "0 * * * *" }
         ]
       }
     * ФОНОВЫЕ ПРОЦЕССЫ: В Route Handlers никогда не оставляй висящие не-await промисы. На Vercel лямбда замораживается при возврате ответа. Обязательно используй 'await' или 'waitUntil' из '@vercel/functions'.
   - Добавь полученную ссылку на живое демо в начало README.md в раздел 'Live Demo'.

7. ИЗОЛЯЦИЯ ОШИБОК И НАДЕЖНОСТЬ ПАКЕТНОЙ ОБРАБОТКИ (PER-ITEM ISOLATION):
   - Оборачивай обработку каждой сущности (каждой игры/записи) в независимый 'try / catch'. Ошибка на 20-й записи не должна прерывать или откатывать предыдущие 19 успешно собранных записей!
