# О-комплекс: ИИ-Ассистент менеджера AmoCRM

Production-ready сервис и интерфейс интеграции для AmoCRM. Принимает обращение клиента в диалоговом окне сделки, сопоставляет его с базой знаний регламентов компании "О-комплекс" и выдает два обязательных блока:
1. **Вежливый экспертный ответ клиенту** (готовый для копирования, вставки в драфт или моментальной отправки).
2. **Подсказку по допродажам для менеджера** (выделение триггера боли, ценностное предложение, прирост чека и готовая реплика-пивот для диалога).

## Архитектура и технические решения

Проект построен на модульной масштабируемой архитектуре:

1. **Frontend / UI**:
   - Next.js 14 App Router + React 18 + Tailwind CSS (минималистичная палитра Slate/Zinc в стиле AmoCRM Dark Theme, без кричащих градиентов).
   - Интерактивный эмулятор окна диалога AmoCRM с контекстом сделки (статус воронки, контактные данные, бюджет, история сообщений).
   - Предустановленные сценарии обращений ("Интеграция 1С и остатки", "Потеря заявок ночью / AI-бот", "Базовое внедрение AmoCRM", "Телефония и контроль звонков").
   - Панель AI-виджета менеджера с поддержкой переключения движка (Auto / Groq / Gemini / Deterministic) и телеметрией задержки.

2. **Knowledge Base Engine (`src/lib/kb/knowledge-base.ts`)**:
   - Структурированная база знаний регламентов, тарифов и сроков компании "О-комплекс".
   - Алгоритм ранжирования с нормализацией токенов (поддержка кириллицы/латиницы 1С/1C, стемминг, учет тегов и заголовков).

3. **Upsell Matrix (`src/lib/kb/upsell-rules.ts`)**:
   - Матрица триггеров болей клиента (потеря ночного трафика, ручные счета, отсутствие контроля звонков).
   - Формирование реплики-скрипта (pitch) для менеджера с оценкой потенциала допродажи (+25 000 ₽ ... +60 000 ₽ к сделке).

4. **AI Multi-Provider Dispatcher (`src/lib/ai/ai-service.ts`)**:
   - Первичный провайдер: **Groq API** (`qwen/qwen3.8-27b`) — ультрабыстрый инференс (до 150 мс).
   - Вторичный провайдер: **Google Gemini API** (`gemini-2.5-flash`).
   - Автоматический failover на **Deterministic Rule Engine** при сетевых сбоях или исчерпании лимитов внешних API, что исключает 500-е ошибки на продакшене.

5. **API & Интеграции**:
   - `POST /api/assist` — основной эндпоинт генерации ответа и подсказки (валидация Zod, изоляция ошибок, маскирование токенов).
   - `POST /api/amocrm/webhook` — обработчик входящих событий AmoCRM Digital Pipeline / Salesbot (с защитой от зацикливания исходящих сообщений менеджера).
   - `GET /api/kb` — API поиска и получения базы знаний.
   - `GET /api/health` — мониторинг работоспособности, времени аптайма и статуса провайдеров.

## Тестирование (100% Green Test Suite)

Проект покрыт 31 тестом (Unit и Integration) с использованием Vitest и Testing Library:
- **Unit-тесты**:
  - `knowledge-base.test.ts` — релевантность поиска, нормализация 1C/1С, граничные случаи.
  - `upsell-rules.test.ts` — точность срабатывания триггеров и расчет confidence score.
  - `deterministic-engine.test.ts` — проверка структуры блоков 1 и 2 без внешних API.
  - `prompt-builder.test.ts` — сборка системного и пользовательского промпта.
  - `validation-schemas.test.ts` — валидация Zod для входящих и исходящих данных.
- **Интеграционные тесты API**:
  - `assist-api.test.ts` — проверка POST `/api/assist` (200, 400, 422, контекст лида).
  - `amocrm-webhook-api.test.ts` — проверка POST `/api/amocrm/webhook`, защита от циклов.
  - `kb-api.test.ts` — фильтрация статей и правил допродаж по запросу и типам.
  - `health-api.test.ts` — проверка телеметрии и статуса готовности.

Запуск тестов:
```bash
npm test
```

## Запуск в Docker Compose

Для воспроизводимого локального развертывания одной командой:

```bash

docker compose up -d --build

# Проверка статуса контейнера и healthcheck
docker compose ps

# Проверка логов
docker compose logs -f
```

Приложение станет доступно по адресу `http://localhost:3000`.

## Локальный запуск (Node.js)

Требования: Node.js 20+

1. Установка зависимостей:
   ```bash
   npm install
   ```

2. Настройка переменных окружения:
   Скопируйте `.env.example` в `.env.local`:
   ```bash
   cp .env.example .env.local
   ```

3. Проверка типов TypeScript:
   ```bash
   npm run type-check
   ```

4. Запуск в режиме разработки:
   ```bash
   npm run dev
   ```

5. Сборка production-бандла:
   ```bash
   npm run build
   npm start
   ```

## Реализовано в продакшене vs Известные ограничения внешних источников

### Реализовано в продакшене:
- Полнофункциональный интерфейс рабочего места менеджера AmoCRM.
- Генерация двух независимых блоков (ответ клиенту + допродажа для менеджера).
- Управление базой знаний и просмотр матрицы триггеров через модальное окно.
- Эмулятор входящих вебхуков AmoCRM с генерацией рабочих cURL-команд.
- Серверная валидация схем через Zod и failover-устойчивость.

### Известные ограничения внешних источников:
- Внешние LLM API (Groq, Gemini) могут подвергаться временным сетевым задержкам или rate-limit ограничениям. В проекте это решено автоматическим переключением на локальный Deterministic Rule Engine, возвращающий точные ответы по базе регламентов с нулевой задержкой.
